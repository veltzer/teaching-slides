When writing marp:
- every lecture or course must start with a slide which has the name of the lectures/course and my name and email. Copy it from other lectuers and courses.
- every lecture or course must have a drawing on the second slide about the topic in question.
- do not add a "marp" section ("---") at the beginning.
- only one heading should have one hash mark (#)
- all other headings should have two hash marks (##) or more.
- never leave lines with spaces or tabs at the end, not even when writing code samples
- when enumerating items use 1. 1. 1. and not 1. 2. 3.
- indent sub items with four spaces like this "    - [text]"
- do not use mermaid until we have a rust fast mermaid tool.
- do not add a "Any Questions slide".
- call the file for each chapter [number]_[name].md from 00. For instance: 00_intoduction.md
- files should end with a newline, on the last line that is.
- don't do consecutive blank lines.
- remember to keep "---" separators between the slides for them to be rendered correctly.
- do about right number of slides per chapter. Not more and not less than the amount need to sensibly teach that chapter.
- keep technical terms within backticks (`).
- always create marp slides as a "markdown" document and not "text" document so that I could copy the markdown content.
- remember that each slide needs to have short content and that code in it needs to be short enough to appear in one page.
- when you want to do a table just do a markdown table.

- if you want to add mermaid diagrams then add these lines:

```marp
<!-- Add Mermaid.js support -->
<script src="https://cdn.jsdelivr.net/npm/mermaid@10/dist/mermaid.min.js"></script>
<script>
  mermaid.initialize({ startOnLoad: true });
</script>
```

in the mermaid file and then add mermaid content like this:

```marp
<div class="mermaid">
graph TD
    A[Client] -->|TCP Connection| B[Load Balancer]
    B -->|TCP Connection| C[Server1]
    B -->|TCP Connection| D[Server2]
</div>
```

- always do a newline *before* ```
- if you want to add text in a different language *always* specific a language after the ```.
	If you just want to add pure text just write ```txt.
- when doing list offset by 4 space. Not 2. Not tabs.
- when doing numeric lists always do:
    1.
    1.
    1.
    and not
    1.
    2.
    3.
      The rendered will take care of the numbers.

## SVG Guidelines

Prefer SVG to mermaid and avoid ascii art diagrams.

- do not use inlined SVG. Write the SVG externally in the svg/ folder and reference it from the slides.
- do not reference external images via http/https URLs. All images must be local files
  in the svg/ or jpg/ directories.
- image references (![...](path)) must point to files that actually exist. Run the
  md_checks.py --images check to verify.
- SVG files must use a fixed viewBox of exactly 1280x720 (16:9, matches Marp slide
  dimensions). Use scripts/fix_svg_aspect_ratio.py to convert existing SVGs.
  The check_svg.py --dimensions check enforces this.
- SVG diagrams must use font-size of at least 10. Anything smaller is unreadable in
  presentations. The check_svg.py --fonts check enforces this.
- SVG files must be properly formatted multi-line XML. Never generate single-line SVGs
  or truncated stubs. Each SVG should have at least 5 XML elements.
- A slide that contains an SVG drawing must have ONLY the ## heading and the image
  reference — nothing else. No bullet points, no text, no code before or after the image.
  If you have content that belongs with the drawing, put it on a separate slide before
  or after: either a text-only slide introducing the diagram, or a follow-up slide
  discussing it.

Note: inline SVG is no longer used. Do not do this:

```marp
<svg viewBox="0 0 200 200" xmlns="http://www.w3.org/2000/svg">
  <!-- Main circle -->
  <circle cx="100" cy="100" r="80" fill="#f0f0f0" stroke="#333" stroke-width="2"/>
</svg>
```

## Common problems found in the past (avoid repeating these)

- do not leave empty slides (two consecutive "---" separators with nothing between them).
- always close code fences. Every opening ``` must have a matching closing ```.
  A common mistake is opening a code block and then starting a new slide (---) without
  closing the code block first.
- every lecture must have YAML front matter (tags, level, category, audience) just like
  courses do.
- do not put content (bullet points, descriptions, images) on the title slide (slide 1).
  The title slide should only have # Title, ## Author, ## Email. Diagrams and content
  go on slide 2 and beyond.
