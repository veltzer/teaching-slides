## SVG Guidelines

- always use the same pallette for slides (resources/svg_palette.svg)
- SVG diagrams must NOT contain a title element. The slide's ## heading is the title. Adding a title inside the SVG wastes vertical space because Marp renders the heading above the image, shrinking the area available to the diagram.
- SVG content must not extend below y=640. Marp takes the markdown header (e.g. `## Slide Title`) and renders it at the top of the slide, pushing the SVG down. By restricting drawings to the top 640 pixels, you leave a blank "buffer" area at the bottom so that when Marp shifts the image down, your actual drawing doesn't get pushed off the bottom edge of the screen or get clipped. The check_svg.py --bounds check enforces this limit.
- SVG files must use a fixed viewBox of exactly 1280x720 (16:9, matches Marp slide dimensions). Do NOT change the viewBox to 1280x640. A 1280x640 viewBox changes the aspect ratio to 2:1, causing Marp to distort, stretch, or improperly center the image. Use scripts/fix_svg_aspect_ratio.py to convert existing SVGs to 1280x720. The check_svg.py --dimensions check enforces this.
- if there is SVG in a line there could be only one line of text above it or one line of text below it. But no more than 1 line above or below (Not both).
- Prefer SVG to mermaid and avoid ascii art diagrams.
- do not use inlined SVG. Write the SVG externally in the svg/ folder and reference it from the slides.
- do not reference external images via http/https URLs. All images must be local files
  in the svg/ or jpg/ directories.
- image references (![...](path)) must point to files that actually exist. Run the
  md_checks.py --images check to verify.
- SVG diagrams must use font-size of at least 10. Anything smaller is unreadable in
  presentations. The check_svg.py --fonts check enforces this.
- SVG files must be properly formatted multi-line XML. Never generate single-line SVGs
  or truncated stubs. Each SVG should have at least 5 XML elements.
- A slide that contains an SVG drawing must have ONLY the ## heading and the image
  reference — nothing else. No bullet points, no text, no code before or after the image.
  If you have content that belongs with the drawing, put it on a separate slide before
  or after: either a text-only slide introducing the diagram, or a follow-up slide
  discussing it.

Note: inline SVG is no longer used. Do not do this:

```marp
<svg viewBox="0 0 200 200" xmlns="http://www.w3.org/2000/svg">
  <!-- Main circle -->
  <circle cx="100" cy="100" r="80" fill="#f0f0f0" stroke="#333" stroke-width="2"/>
</svg>
```
