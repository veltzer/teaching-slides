# Game Days

---

## What This Chapter Covers

- What a game day is
- Planning
- Roles
- Running the day
- Aftermath

---

## What A Game Day Is

- Scheduled chaos exercise
- Cross-team participation
- Realistic scenarios
- Time-bounded

---

## Why Schedule

- Forces action
- Trains responders
- Tests runbooks
- Builds muscle memory

---

## Planning

- Pick a scenario
- Pick a date
- Communicate widely
- Prepare materials

---

## Game Day Phases

![game_day_phases](svg/courses/testing/chaos-engineering/04_game_days/game_day_phases.svg)

---

## Scenario Design

- Realistic but bounded
- Multiple steps
- One scenario per day
- Document exit criteria

---

## Roles

- Game master runs the show
- Responders respond
- Observers watch and note
- Stakeholders read the report

---

## Roles Visualized

![game_day_roles](svg/courses/testing/chaos-engineering/04_game_days/game_day_roles.svg)

---

## Pre-Brief

- Recap roles
- State scenario constraints
- State communication channels
- Confirm abort triggers

---

## Running The Day

- Inject the failure
- Let responders respond
- Observers stay quiet
- Game master coordinates

---

## Communication Discipline

- One incident channel
- Status updates on a clock
- Clear ownership of decisions
- Practice the same as real incidents

---

## Stuck Moments

- Missing tools
- Missing access
- Missing knowledge
- Each is an action item

---

## Recovery

- End the experiment cleanly
- Verify steady state
- Hand back to normal operations
- Save artifacts for review

---

## Debrief

- Run blameless review
- Walk timeline
- List what went well
- List what to improve

---

## Action Items

- Owners and deadlines
- Tracked in your tool
- Revisited at next game day
- Block next game day if not done

---

## Frequency

- Quarterly minimum
- Each major service
- Increase pre-launch
- Adapt to risk

---

## Common Game Day Mistakes

- Too few participants
- Game master also a responder
- No abort plan
- No follow-up actions
- Same scenario every time
