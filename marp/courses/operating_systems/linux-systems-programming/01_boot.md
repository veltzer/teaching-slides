## Firmware Types

## BIOS (Legacy)
- **Basic Input/Output System**
- 16-bit real mode operation
- MBR partition scheme limitation (2TB max)
- Simple but limited

## UEFI (Modern)
- **Unified Extensible Firmware Interface**
- 32/64-bit protected mode
- GPT partition support
- Secure Boot capability

---

## Boot Process: BIOS vs UEFI

## BIOS Boot
1. POST → BIOS initialization
1. Read MBR (first 512 bytes)
1. Execute MBR bootloader
1. Chain load to partition bootloader

## UEFI Boot
1. POST → UEFI initialization
1. Read ESP (EFI System Partition)
1. Execute EFI application directly
1. Optional: Secure Boot verification

## GRUB Boot Process

1. **Stage 1**: Boot sector code (446 bytes)
1. **Stage 1.5**: File system drivers
1. **Stage 2**: Main GRUB functionality
1. **Menu Display**: User selection
1. **Kernel Loading**: Load vmlinuz
1. **InitRD Loading**: Load initial ramdisk
1. **Handoff**: Transfer control to kernel

## What is Secure Boot?

## Key Concepts:
- **Cryptographic verification** of boot components
- **Chain of trust** from hardware to OS
- **Prevention** of rootkits and bootkits
- **UEFI standard** feature (since 2.3.1)

## Requirements:
- UEFI firmware
- Signed bootloader
- Signed kernel
- Key management

---

## Secure Boot Keys Hierarchy

## Four Key Databases:

1. **PK (Platform Key)**
    - Top-level key
    - One key only
    - Controls KEK updates

1. **KEK (Key Exchange Key)**
    - Second level
    - Updates db/dbx
    - Multiple keys allowed

1. **db (Signature Database)**
    - Allowed signatures
    - Trusted certificates

1. **dbx (Revoked Signatures)**
    - Blacklisted signatures
    - Compromised certificates

---

## Secure Boot Process Flow

```misc
1. Power On → UEFI Firmware starts
2. Verify PK is enrolled
3. Load bootloader from ESP
4. Check signature against db
5. Check not in dbx (revoked)
6. If valid �� Execute bootloader
7. Bootloader verifies kernel
8. Kernel verifies modules
9. Continue boot process
```

## TPM Key Hierarchy

## Key Types:

1. **EK (Endorsement Key)**
    - Permanent, unique per TPM
    - Identifies the TPM

1. **SRK (Storage Root Key)**
    - Root of storage hierarchy
    - Protects other keys

1. **AIK (Attestation Identity Key)**
    - Platform attestation
    - Privacy-preserving

1. **Binding/Signing Keys**
    - User-generated
    - Application-specific

---

## Platform Configuration Registers (PCRs)

## PCR Usage (TPM 2.0 - 24 registers):

```misc
PCR 0:  BIOS/UEFI firmware
PCR 1:  BIOS/UEFI configuration
PCR 2:  Option ROMs
PCR 3:  Option ROM configuration
PCR 4:  MBR/Boot sector
PCR 5:  Boot configuration
PCR 6:  Platform manufacturer specific
PCR 7:  Secure Boot state
PCR 8-15: Operating system use
PCR 16: Debug
PCR 17-22: DRTM (Dynamic Root of Trust)
PCR 23: Application specific
```

---

## TPM Operations

## Core Functions:

1. **Sealing/Unsealing**
    - Encrypt data to PCR state
    - Decrypt only if PCRs match

1. **Remote Attestation**
    - Prove platform state
    - Cryptographic evidence

1. **Key Management**
    - Generate keys
    - Store keys securely

1. **Random Numbers**
    - True RNG
    - Cryptographic quality

---

## Measured Boot Process

```bash
# Each component measures the next
1. BIOS → Measure bootloader → Extend PCR 4
2. Bootloader → Measure kernel → Extend PCR 8
3. Kernel → Measure initrd → Extend PCR 9
4. Init → Measure services → Extend PCR 10

# PCR Extend Operation (cannot undo)
PCR[n] = SHA256(PCR[n] || new_measurement)
```

## Implementing Secure Boot on Linux

## Steps:

```bash
# 1. Check Secure Boot status
mokutil --sb-state

# 2. Import MOK (Machine Owner Key)
mokutil --import my-key.der

# 3. Sign kernel modules
/usr/src/linux-headers-*/scripts/sign-file \
    sha256 ./MOK.priv ./MOK.der module.ko

# 4. Verify signatures
hexdump -C module.ko | tail
```

## Debugging Boot Issues

## Common Problems:

1. **Secure Boot Violation**
    - Unsigned bootloader/kernel
    - Solution: Sign or disable

1. **TPM Not Detected**
    - Check BIOS settings
    - Enable TPM device

1. **PCR Mismatch**
    - Configuration changed
    - Reseal secrets

1. **Key Management**
    - Lost keys
    - Backup critical keys
