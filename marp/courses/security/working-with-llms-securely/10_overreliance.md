# LLM09: Overreliance
## The Danger of Trusting `LLMs` Too Much

---

## What is Overreliance?

- Users or systems **trust `LLM` outputs without verification**
- `LLMs` generate plausible but **incorrect or fabricated** content
- Lack of human oversight leads to **flawed decisions**
- Overreliance is a **human vulnerability**, not just a technical one

---

## Why `LLMs` Produce Unreliable Output

- `LLMs` are **statistical pattern matchers**, not knowledge bases
- They generate the **most probable next token**, not the most truthful
- They have **no concept** of truth, accuracy, or correctness
- They **hallucinate** — confidently generate false information
- They have **knowledge cutoffs** and cannot access real-time data

---

## Hallucination Examples

```console
User: "What is the CVE number for the Log4Shell
vulnerability?"

LLM: "The Log4Shell vulnerability is CVE-2021-44228."
      ✓ Correct

User: "What is the CVE for the critical vulnerability
in FooBarLib 3.2?"

LLM: "The critical vulnerability in FooBarLib 3.2
is CVE-2023-98765."
      ✗ Completely fabricated CVE number
```

The `LLM` presents both answers with equal confidence

## Overreliance in Code Generation

```python
# LLM-generated code that looks correct but has a bug
def is_leap_year(year):
    """Check if a year is a leap year."""
    if year % 4 == 0:
        if year % 100 == 0:
            return False  # Bug! Missing %400 check
        return True
    return False

# Correct implementation requires:
# if year % 400 == 0: return True
# if year % 100 == 0: return False
# if year % 4 == 0: return True
```

## Overreliance in Security Contexts

```console
Developer: "Is this code secure?"

LLM: "Yes, this code follows security best practices.
The input is properly validated and the output is
correctly sanitized."

Reality: The code has a SQL injection vulnerability
that the LLM failed to identify because the pattern
didn't match its training data.
```

Using an `LLM` as the **sole** security reviewer is dangerous

---

## Overreliance in Legal and Medical Contexts

- Lawyers have cited **fictitious court cases** generated by `LLMs`
- Medical advice from `LLMs` may be **dangerously incorrect**
- Financial analysis may be based on **hallucinated data**
- Compliance recommendations may **miss critical regulations**

> In 2023, a New York lawyer was sanctioned for submitting `ChatGPT`-generated legal briefs containing fabricated case citations

---

## Risks of Overreliance in Production Systems

| Scenario | Risk |
|----------|------|
| `LLM` auto-generates code | Vulnerable code deployed |
| `LLM` writes documentation | Incorrect docs mislead developers |
| `LLM` classifies security alerts | False negatives miss real threats |
| `LLM` approves transactions | Fraudulent transactions approved |
| `LLM` generates reports | Decisions based on fabricated data |

## Mitigation: Verification Workflows

```python
def generate_with_verification(prompt):
    response = llm.generate(prompt)

    # Cross-reference with authoritative sources
    facts = extract_factual_claims(response)
    for fact in facts:
        verified = verify_against_source(fact)
        if not verified:
            response = add_warning(response, fact)

    # Add confidence indicators
    response = add_confidence_metadata(response)

    return response
```

## Mitigation: Grounding with `RAG`

```python
def grounded_response(user_query):
    # Retrieve relevant documents from trusted sources
    docs = vector_db.search(user_query, limit=5)

    prompt = f"""
    Answer the question using ONLY the provided documents.
    If the answer is not in the documents, say
    "I don't have enough information to answer this."

    Documents: {docs}

    Question: {user_query}
    """

    response = llm.generate(prompt)
    return response, docs  # Return sources for verification
```

## Mitigation: Testing `LLM`-Generated Code

```python
# Always run tests on LLM-generated code
def review_llm_code(generated_code: str):
    checks = []

    # Static analysis
    checks.append(run_linter(generated_code))
    checks.append(run_sast(generated_code))  # Security scan

    # Dynamic testing
    checks.append(run_unit_tests(generated_code))
    checks.append(run_fuzzer(generated_code))

    # Human review for critical code
    if is_security_critical(generated_code):
        checks.append(request_human_review(generated_code))

    return all(c.passed for c in checks)
```

## Key Takeaways

- `LLMs` **hallucinate** — they generate plausible but false content
- Never use `LLM` output as the **sole basis** for critical decisions
- Implement **verification workflows** and **grounding** with trusted sources
- Add **confidence indicators** and **source citations** to outputs
- **Test all `LLM`-generated code** with static analysis, tests, and human review
- **Educate users** on `LLM` limitations to prevent automation bias
